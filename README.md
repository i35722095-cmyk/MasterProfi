# MasterProfi AI Agent

Агент формирует коммерческие предложения по ТЗ с использованием Python. По умолчанию используется ChatGPT через OpenAI API; также можно выбрать локальную Qwen через Ollama либо облачные Claude, DeepSeek или Qwen через API.

Для установки на новый Mac с нуля используйте [SETUP_MAC.md](SETUP_MAC.md); для Windows — [SETUP_WINDOWS.md](SETUP_WINDOWS.md).

## Запуск

macOS:

```bash
python3 -m venv .venv
.venv/bin/pip install -r requirements.txt
./run_agent.command
```

Windows (PowerShell или cmd.exe):

```bat
python -m venv .venv
.venv\Scripts\pip install -r requirements.txt
run_agent.bat
```

Если в `config/llm.toml` настроено больше одной модели, при запуске в Терминале появится меню выбора: стрелками `↑`/`↓` выберите модель и нажмите `Enter`. Без интерактивного Терминала (например, при запуске в фоне) агент использует модель, указанную в поле `provider` файла `config/llm.toml`.

## Выбор модели

- **ChatGPT (OpenAI)** — используется по умолчанию. Перед запуском в PowerShell задайте ключ: `$env:OPENAI_API_KEY="sk-..."`. В macOS/Linux: `export OPENAI_API_KEY="sk-..."`.
- **Локально (Ollama)** — ничего не отправляется в интернет. Установите модель командой `ollama pull qwen3.5:9b` и запустите Ollama перед стартом агента.
- **Claude (Anthropic)** — облачная модель. Перед запуском задайте ключ:
  ```bash
  export ANTHROPIC_API_KEY=sk-ant-...
  ```
- **DeepSeek** — облачная модель. Перед запуском задайте ключ:
  ```bash
  export DEEPSEEK_API_KEY=...
  ```
- **Qwen через API (Alibaba Cloud DashScope)** — облачная версия Qwen. Перед запуском задайте ключ:
  ```bash
  export DASHSCOPE_API_KEY=...
  ```

Ключи API нигде не хранятся в репозитории — только в переменных окружения текущего сеанса Терминала. Настройки моделей (имя модели, адрес API, лимиты) находятся в `config/llm.toml`, подробности — в [config/README.md](config/README.md). При облачных моделях содержимое ТЗ (наименования, размеры, количество позиций) отправляется во внешний API соответствующего провайдера — используйте локальную Ollama, если это неприемлемо.

Перед первым запуском положите локальный прайс в `Локальные данные/`, примеры ТЗ в `ПримерыТЗ/`, а старые КП для RAG и сверки — в `ПримерыКП/`. Эти каталоги содержат коммерческие и клиентские данные и намеренно не публикуются в Git. Готовое КП формируется непосредственно в PDF без Excel-шаблона.

Положите ТЗ в `input/`. Поддерживаются XLSX, DOCX и PDF. Для каждого ТЗ агент создаёт отдельную папку в `output/`:

- PDF без файла `Ручной_расчет.txt` означает, что расчёт успешно завершён; исходный файл после этого удаляется из `input/`;
- `Требуется_уточнение.txt` означает, что для одной или нескольких позиций нет подтверждённого правила. В файле написано, что именно нужно уточнить; исходное ТЗ остаётся в `input/`;
- `Требуется_уточнение.json` — технические данные для специалиста, менеджеру их редактировать не нужно.
- если в интерактивном меню выбран вариант «Не рассчитывать», агент создаёт частичное КП по остальным позициям и файлы `Ручной_расчет.txt`/`.json`. В них перечислены позиции, которые не вошли в итог и должны быть рассчитаны и добавлены менеджером вручную; исходное ТЗ после формирования результата удаляется из `input/`.

Если агент запущен через `./run_agent.command`, он может задать уточняющий вопрос прямо в Терминале. Выбранная модель помогает сформулировать вопрос, но не назначает цены сама: автоматически применяется только явно выбранное пользователем подтверждённое правило.

Если название ткани совпало с прайсом только частично, агент не назначает цену автоматически. В Терминале он показывает до трёх наиболее похожих вариантов из локального прайса с категорией и ставкой. Цена применяется только после явного выбора менеджера; вариант «Не рассчитывать» переносит позиции в отчёт для ручного расчёта.

Если менеджер выбрал альтернативу из прайса, клиентское КП содержит заметное предупреждение, а соответствующая строка выделяется цветом и показывает замену в формате `исходный материал → выбранная альтернатива`.

## Что извлекается из ТЗ

- наименование позиции;
- ширина и высота либо площадь;
- количество.

Скидка, монтаж и доставка временно исключены из расчёта.

## Как менеджеру читать результат

Откройте самую новую папку в `output/`. Она относится к одному конкретному запуску ТЗ.

- Если внутри есть только PDF `КП_…pdf`, КП успешно проверено и готово к отправке клиенту.
- Если рядом с PDF есть `Ручной_расчет.txt`, КП сформировано частично: перечисленные в отчёте позиции не входят в итог. Рассчитайте их и скорректируйте КП вручную перед отправкой клиенту.
- Если внутри есть `Требуется_уточнение.txt`, откройте его: там написано, какая позиция не рассчитана и что именно нужно уточнить. После добавления правила или аналога в конфиг перезапустите агента; исходное ТЗ останется в `input/`.
- Файл `Требуется_уточнение.json` менеджеру обычно не нужен. Это техническая детализация для диагностики агента.
- Если отчёт сообщает о технической проверке, не редактируйте КП вручную: передайте TXT-отчёт техническому специалисту.

## Структура

- `source/main.py` — неизменная точка запуска и наблюдение за `input`;
- `source/agent/` — оркестрация, маршрутизатор навыков, короткие промпты и адаптеры LLM: локальная Ollama, Claude, DeepSeek и Qwen через API;
- `source/tools/` — детерминированные инструменты разбора ТЗ, прайса, PDF и проверки;
- `source/memory/` — SQLite/RAG, аналоги и источники конкурентов;
- `source/ui/` — терминальное меню уточнений;
- `source/core/` — пути проекта, модели и нейминг результатов;
- `source/skills/` — описания бизнес-навыков без загрузки всего текста в контекст Qwen;
- `source/prompts/` — общие правила работы LLM;
- `config/` — прокомментированные настройки TOML, включая аналоги конкурентов;
- `source/knowledge/` — техническая локальная база RAG/SQLite.
- `output/2026-09-01_21-20_<название-ТЗ>_<id>/` — отдельная папка одного запуска: готовый или частичный КП либо отчёт, блокирующий выпуск. Предложение называется `КП_<название-ТЗ>.pdf`; ручные позиции перечисляются в `Ручной_расчет.txt`, а блокирующие проблемы — в `Требуется_уточнение.txt`.

## Безопасность расчёта

RAG помогает понять структуру и найти подтверждённый аналог, но не является источником нашей цены. Итоговая цена должна иметь происхождение из локального прайса. Непроверенные аналоги и позиции без ценового правила блокируют выпуск КП.
