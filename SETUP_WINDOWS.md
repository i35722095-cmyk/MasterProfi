# Установка MasterProfi AI Agent на чистый Windows-ноутбук

Эта инструкция разворачивает агента на новом Windows-компьютере с нуля. В конце он будет ждать ТЗ в папке `input/` и создавать отдельную папку с результатом для каждого запуска обработки в `output/`.

## Что потребуется

- Windows 10 (сборка 1511 и новее) или Windows 11 — нужны для корректной работы цветного меню в консоли.
- Права администратора для установки программ на компьютере.
- Доступ в интернет только на этапе установки Python-библиотек и модели Qwen (или на постоянной основе — при использовании облачных моделей Claude/DeepSeek/Qwen API).
- Приватная копия локального прайса и, при необходимости, примеров ТЗ/КП. Эти коммерческие файлы не хранятся в Git.

## 1. Проверить инструменты

Откройте **PowerShell** и выполните:

```powershell
git --version
python --version
```

Если обе команды отработали, ничего устанавливать не нужно. Подходит Python 3.11 и новее (более новые версии могут не иметь готовых сборок для некоторых зависимостей — см. раздел «Частые проблемы»).

Если не найдена команда `git`, установите [Git for Windows](https://git-scm.com/download/win) (используйте настройки по умолчанию).

Если не найдена команда `python`, установите Python с [python.org](https://www.python.org/downloads/windows/) — на первом экране установщика обязательно включите галочку **Add python.exe to PATH**, затем откройте новое окно PowerShell.

## 2. Установить Ollama и модель

Скачайте `OllamaSetup.exe` с [официальной страницы Ollama](https://ollama.com/download/windows) и установите его (устанавливается как обычная программа для текущего пользователя).

Затем в PowerShell выполните:

```powershell
ollama --version
ollama pull qwen3.5:9b
ollama list
```

Последняя команда должна показать `qwen3.5:9b`. Имя модели должно совпадать со значением `model` в `config/llm.toml`.

Если вместо локальной модели планируется использовать облачную (Claude, DeepSeek или Qwen через API), этот шаг можно пропустить — см. раздел «Выбор модели» в [README.md](README.md).

## 3. Скачать код агента

В PowerShell:

```powershell
mkdir C:\AI-Agents
git clone https://github.com/VDevGushin/MasterProfi.git C:\AI-Agents\Ivan-Work
cd C:\AI-Agents\Ivan-Work
```

Если репозиторий закрытый, сначала войдите в GitHub через Fork или настройте доступ по SSH.

## 4. Создать Python-окружение и установить библиотеки

В папке проекта выполните:

```powershell
python -m venv .venv
.venv\Scripts\python.exe -m pip install -r requirements.txt
```

Папка `.venv\` создаётся только на этом компьютере. Её не нужно копировать, отправлять в Git или редактировать.

Если установка упадёт на пакете `pdfplumber` (точнее, на его зависимости `pypdfium2`) — см. раздел «Частые проблемы» ниже.

## 5. Добавить локальные данные

В Git намеренно нет клиентских и коммерческих файлов. С защищённого носителя или старого компьютера скопируйте в проект:

```text
Локальные данные\  — актуальный XLSX-прайс (обязательно для расчёта)
ПримерыТЗ\         — примеры входных ТЗ (желательно: нужны для тестов и RAG)
ПримерыКП\         — старые КП (желательно: нужны для RAG и сверки)
```

Папки `input\` и `output\` уже есть. В `input\` кладут новые ТЗ, а `output\` агент заполняет сам: для каждого запуска создаётся отдельная папка результата с датой, названием ТЗ и идентификатором.

## 6. Настроить агента

Все настройки находятся в папке `config\`:

- `config\agent.toml` — курс, гарантия, срок изготовления;
- `config\llm.toml` — провайдер, имя модели и лимиты LLM;
- `config\competitors.toml` — подтверждённые аналоги тканей конкурентов;
- `config\competitor_sources.toml` — справочные сайты конкурентов.

Не меняйте названия полей слева от `=`. Подробности — в `config\README.md`.

Если планируется использовать облачную модель (Claude, DeepSeek или Qwen через API), задайте нужный ключ перед запуском — переменная действует только в текущем окне PowerShell:

```powershell
$env:ANTHROPIC_API_KEY = "sk-ant-..."
$env:DEEPSEEK_API_KEY = "..."
$env:DASHSCOPE_API_KEY = "..."
```

Чтобы ключ сохранился и после перезапуска компьютера, используйте `setx` вместо `$env:` (потребует открыть новое окно PowerShell, чтобы значение подхватилось):

```powershell
setx ANTHROPIC_API_KEY "sk-ant-..."
```

## 7. Проверить установку

Если скопированы прайс и все примеры, выполните:

```powershell
.venv\Scripts\python.exe -m source.tests.test_agent
```

Ожидаемый результат:

```text
OK
```

Если примеров ещё нет, этот тест пропустите: для рабочего расчёта достаточно локального прайса.

## 8. Запустить агента

В папке проекта:

```powershell
run_agent.bat
```

или двойным щелчком по файлу `run_agent.bat` в Проводнике.

Должно появиться сообщение:

```text
Агент запущен. Ожидаю XLSX, DOCX, PDF или TXT в папке input.
```

Дальше:

1. Положите ТЗ формата XLSX, DOCX, PDF или TXT в `input\`.
2. Следите за ходом расчёта в консоли.
3. Откройте самую новую папку с датой и названием ТЗ в `output\`.
4. Если внутри находится PDF-КП — расчёт завершён; его можно передавать клиенту. Агент удалит исходное ТЗ из `input\` только после успешной проверки КП.
5. Если вместо PDF появился `Требуется_уточнение.txt`, откройте его: там простыми словами указана проблемная позиция и нужное решение. Исходное ТЗ остаётся в `input\`; после уточнения правила расчёта запустите агента повторно.

Файл `Требуется_уточнение.json` в этой же папке — технические данные для специалиста. Менеджеру не нужно его открывать или редактировать.

Если запустить `run_agent.bat` двойным щелчком и в конфиге настроено больше одной модели LLM, появится меню выбора: стрелками `↑`/`↓` выберите модель и нажмите `Enter`.

Остановить агента: `Ctrl + C` в окне консоли (или просто закрыть окно).

## Частые проблемы

| Сообщение | Что сделать |
| --- | --- |
| `'python' is not recognized as an internal or external command` | Переустановите Python с python.org, включив галочку «Add python.exe to PATH», и откройте новое окно PowerShell. |
| `git : The term 'git' is not recognized...` | Установите [Git for Windows](https://git-scm.com/download/win) и откройте новое окно PowerShell. |
| `File ... cannot be loaded because running scripts is disabled on this system` (при активации venv через `Activate.ps1`) | Не обязательно активировать окружение — этот проект всегда вызывает `.venv\Scripts\python.exe` напрямую. Если всё же нужна активация, один раз выполните `Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass` в текущем окне PowerShell. |
| Ошибка сборки при установке `pdfplumber`/`pypdfium2` (нет готового wheel-пакета под установленную версию Python) | Установите Python 3.11, 3.12 или 3.13 (для них гарантированно есть готовые сборки `pypdfium2`) вместо самой новой версии Python и повторите шаг 4. |
| `ModuleNotFoundError` | Выполните `.venv\Scripts\python.exe -m pip install -r requirements.txt`. |
| `ollama: command not found` / `'ollama' is not recognized` | Переустановите Ollama с официального сайта и откройте новое окно PowerShell. |
| Агент не может связаться с Qwen | Проверьте `ollama list`, запустите Ollama и убедитесь, что имя модели в `config\llm.toml` совпадает с установленным. |
| Нет XLSX-прайса | Скопируйте актуальный файл прайса в `Локальные данные\`. |
| `RuntimeError: Не найден шрифт Arial...` при генерации КП | Штатный Arial есть в любой стандартной установке Windows (`C:\Windows\Fonts\arial.ttf`); если он отсутствует или удалён, установите/восстановите шрифт Arial через «Параметры → Персонализация → Шрифты». |

## Обновление кода

Перед обновлением остановите агента (`Ctrl + C`). Затем в папке проекта:

```powershell
git switch master
git pull
.venv\Scripts\python.exe -m pip install -r requirements.txt
```

Не удаляйте папки `Локальные данные\`, `ПримерыТЗ\`, `ПримерыКП\`, `input\` и `output\`: они не обновляются из Git и содержат локальные данные.
