# Настройки агента

Все файлы этой папки можно редактировать в обычном текстовом редакторе. Не меняйте названия полей слева от `=`.

- `agent.toml` — параметры расчёта, гарантия, срок изготовления, частота проверки папки `input` и включение диалога с пользователем.
- `llm.toml` — настройки LLM. Файл содержит таблицу на каждого провайдера (`[ollama]`, `[claude]`, `[deepseek]`, `[qwen]`) и поле `provider` верхнего уровня — модель по умолчанию, если запуск не интерактивный. Агент выбирает адаптер по полю `provider` внутри выбранной секции.

## Выбор модели LLM

Поддерживаются четыре провайдера:

- `ollama` — локальная модель (по умолчанию Qwen через Ollama), данные не покидают компьютер;
- `claude` — Anthropic Claude через облачный API;
- `deepseek` — DeepSeek через облачный API;
- `qwen` — Qwen через облачный API Alibaba Cloud (DashScope, OpenAI-совместимый режим).

Если запустить агента в интерактивном Терминале, перед стартом появится меню выбора модели (стрелки `↑`/`↓`, `Enter` — подтвердить). Без интерактивного Терминала используется значение поля `provider` в начале `llm.toml`.

Для облачных моделей нужен ключ API в переменной окружения (имя переменной задано полем `api_key_env` в соответствующей секции файла). Ключи никогда не хранятся в `llm.toml` или в Git — задавайте их командой `export` перед запуском:

```bash
export ANTHROPIC_API_KEY=sk-ant-...
export DEEPSEEK_API_KEY=...
export DASHSCOPE_API_KEY=...
```

Если нужный ключ не задан, агент завершится с понятной ошибкой, назвав переменную окружения. При выборе облачной модели содержимое строк ТЗ отправляется во внешний API этого провайдера.
- `competitors.toml` — компании-конкуренты и подтверждённые аналоги тканей. Это основной файл для ручного пополнения базы знаний.
- `competitor_sources.toml` — сайты и каталоги, которые агент может учитывать как справочный источник. Они не являются источником нашей цены.

## Как добавить аналог ткани

1. Откройте `competitors.toml`.
2. Скопируйте закомментированный пример `[[analogue]]` в конце файла.
3. Заполните название ткани конкурента, точную ткань из нашего прайса, категорию и допустимую систему.
4. До проверки оставьте `verified = false`. Агент такую запись проигнорирует.
5. После подтверждения специалистом замените на `verified = true`. При следующей обработке ТЗ агент сможет использовать этот аналог автоматически.

Допустимые категории: `E`, `1`, `2`, `3`, `4`, `5`.

## Диалог при неясной позиции

Если `interactive_clarifications = true`, агент при запуске через `./run_agent.command` задаёт вопрос в Терминале, когда не находит подтверждённое ценовое правило. Qwen формулирует вопрос простым языком, но не имеет права самостоятельно назначать цену или наценку.

Агент показывает меню вариантов прямо в Терминале. Стрелки `↑` и `↓` перемещают выделение, `Enter` подтверждает выбор, а `Esc` отменяет его. Свободного поля «свой ответ» нет: это защищает расчёт от случайных или не относящихся к ТЗ сообщений. Для угловой AMG вариант `1` — рассчитать её как обычную AMG по максимальной ширине; второй вариант оставляет позицию на уточнении. Для других неизвестных правил агент предложит безопасно передать вопрос специалисту, а не станет назначать цену.
